# harness-lambda-service

Creates the Harness native AWS Lambda service entity
(`serviceDefinition.type: AwsLambda`) for a deployed function: the function
definition manifest is sourced from Git, the deployment package from S3.

Called from `iacm/`, so it runs inside the pipeline's IACM stage - the
"Create Service" half of that stage. Keeping it here (rather than in the root
configuration) means the service is reconciled on every deployment instead of
only when someone runs OpenTofu by hand.

## Usage

```hcl
module "harness_lambda_service" {
  source = "../modules/harness-lambda-service"

  service_name        = "my-function"
  org_id              = "default"
  project_id          = "my_project"
  github_connector_id = "github_connector"
  github_branch       = "main"
  aws_connector_id    = "aws_connector"
  aws_region          = "us-east-1"
  artifact_bucket     = "my-function-artifacts-123456789012"
  artifact_key        = "my-function/lambda.zip"
}
```

## Inputs

| Name | Type | Default | Description |
|---|---|---|---|
| `service_identifier` | string | `lambda_service` | Harness service identifier |
| `service_name` | string | – | Display name |
| `org_id` / `project_id` | string | – | Harness scope |
| `github_connector_id` / `github_branch` | string | – | Where the manifest is fetched from |
| `function_definition_path` | string | `harness/function-definition.json` | Manifest path in the repo |
| `aws_connector_id` / `aws_region` | string | – | Connector and region for the S3 artifact source |
| `artifact_bucket` / `artifact_key` | string | – | Deployment package location |

## Outputs

`service_id`, `service_yaml`.

## Note on the manifest

Harness requires every field in an `AwsLambdaFunctionDefinition` manifest to
be camelCase (`functionName`, `memorySize`, …) and rejects a
`code`/`S3Bucket`/`S3Key` block, because it injects the package from the
artifact source itself. The manifest is generated by the root configuration
from `templates/function-definition.json.tftpl`.
